 2. IDEAS BÁSICAS (LO QUE HAY QUE ENTENDER ANTES)
------------------------------------------------------------------------------

 PUNTERO. En lenguajes como C, un puntero es una variable que guarda la
 dirección de memoria donde está un dato. Desreferenciar es llegar al dato
 usando esa dirección.

 REFERENCIA EN PYTHON. En Python toda variable es una referencia a un objeto
 que vive en memoria (el heap). La variable no contiene el dato: apunta a él.

 id(x). Devuelve la identidad del objeto al que apunta x. Es el equivalente
 de la dirección de memoria. Dos variables con el mismo id apuntan al MISMO
 objeto. El operador  is  hace esa misma comparación:

     a is b      es lo mismo que     id(a) == id(b)

 MUTABLE E INMUTABLE.
     Mutables   : list (el objeto se puede modificar en su lugar)
     Inmutables : int, str, tuple (el objeto no se puede modificar; cualquier
                  "cambio" crea un objeto nuevo)

 ALIASING. Cuando dos variables apuntan al mismo objeto mutable. Si se muta
 por una variable, el cambio se ve por la otra. Asignar una lista a otra
 variable NO copia la lista:

     lista_b = lista_a      # una sola lista, dos nombres

 Esquema:

     C (puntero)                    Python (referencia)
     int arr[] = {1,2,3};           arr = [1, 2, 3]
     int *p = arr;                  p = arr          (MISMO objeto)
     p[0] = 99;                     p[0] = 99        (arr[0] también es 99)

 4. LOS EJERCICIOS, UNO POR UNO

 EJERCICIO 1 - id() con enteros                       (Parte 1 del lab)
 ---------------------------------------------------------------------
     a = 42
     b = a
     print(a is b)          ->  True
     b = b + 1
     print(a, b)            ->  42 43
     print(a is b)          ->  False

 Por qué: b = a hace que b apunte al mismo objeto 42. Como los enteros son
 inmutables, b + 1 no cambia el 42: crea un objeto nuevo (43) y b pasa a
 apuntar a él. a sigue apuntando al 42.


 EJERCICIO 2 - Aliasing con listas                    (Parte 2 del lab)
 ---------------------------------------------------------------------
     lista_a = [1, 2, 3]
     lista_b = lista_a
     print(lista_a is lista_b)      ->  True
     lista_b.append(4)
     print(lista_a)                 ->  [1, 2, 3, 4]

 Por qué: solo existe una lista y dos nombres que apuntan a ella. append
 muta el objeto, así que el cambio se ve desde las dos variables. Es el
 mismo caso del esquema de C con  int *p = arr.


 EJERCICIO 3 - Copias de una lista
 ---------------------------------------------------------------------
     original = [1, 2, 3]
     copia1 = original.copy()
     copia2 = list(original)
     copia3 = copy.deepcopy(original)
     copia1.append(99)
     print(original)                ->  [1, 2, 3]
     print(copia1)                  ->  [1, 2, 3, 99]
     print(copia1 is original)      ->  False

 Por qué: las tres formas de copiar crean una lista NUEVA e independiente.
 Mutar copia1 ya no afecta a original. Para listas simples las tres dan el
 mismo resultado; la diferencia aparece con listas anidadas (ejercicio 4).


 EJERCICIO 4 - Copia superficial y copia profunda
 ---------------------------------------------------------------------
     matriz = [[1, 2], [3, 4]]
     superficial = matriz.copy()
     profunda = copy.deepcopy(matriz)
     matriz[0][0] = 99
     print(superficial)             ->  [[99, 2], [3, 4]]
     print(profunda)                ->  [[1, 2], [3, 4]]
     print(superficial[0] is matriz[0])   ->  True
     print(profunda[0] is matriz[0])      ->  False

 Por qué: copy() y list() son copias superficiales: copian la lista de
 afuera, pero las listas de adentro siguen siendo las mismas (se comparten).
 Por eso el cambio en matriz[0][0] se ve en superficial. deepcopy copia todo
 de forma recursiva, así que profunda queda totalmente independiente.


 EJERCICIO 5 - Tipos inmutables
 ---------------------------------------------------------------------
     texto = "hola"
     otro = texto
     otro += " mundo"
     print(texto)                   ->  hola
     print(otro)                    ->  hola mundo

     tupla = (1, 2)
     otra = tupla
     otra = otra + (3,)
     print(tupla)                   ->  (1, 2)
     print(otra)                    ->  (1, 2, 3)

 Por qué: str y tuple no se pueden modificar. La operación += (o +) crea un
 objeto nuevo y la variable pasa a apuntar a él. El objeto original queda
 intacto, así que aquí NO hay aliasing peligroso.


 EJERCICIO 6 - Referencias dentro de funciones
 ---------------------------------------------------------------------
     def agregar_a_lista(lista, valor):
         lista.append(valor)

     def reasignar_lista(lista):
         lista = [0]
         return lista

     datos = [1]
     agregar_a_lista(datos, 2)
     print(datos)                   ->  [1, 2]
     datos2 = [5]
     reasignar_lista(datos2)
     print(datos2)                  ->  [5]

 Por qué: al llamar una función, el parámetro es una referencia al MISMO
 objeto que se pasó. Si la función lo muta (append), el cambio se ve afuera.
 Si la función solo reasigna el nombre (lista = [0]), el nombre local pasa a
 apuntar a otro objeto y el de afuera no se entera.


 EJERCICIO 7 - Lista como parámetro por defecto
 ---------------------------------------------------------------------
     def acumular(valor, lista=[]):
         lista.append(valor)
         return lista

     print(acumular(1))             ->  [1]
     print(acumular(2))             ->  [1, 2]
     print(acumular(3))             ->  [1, 2, 3]

 Por qué: el valor por defecto se crea UNA sola vez, cuando se define la
 función, y todas las llamadas comparten esa misma lista. Es un aliasing
 escondido. Es el ejercicio que más sorprende al predecir. La forma segura
 de escribirlo es  lista=None  y crear la lista dentro de la función.


 EJERCICIO 8 - Mutar in situ o devolver una copia     (Parte 3 del lab)
 ---------------------------------------------------------------------
     def agregar(lista, valor, in_situ=False):
         if in_situ:
             destino = lista
         else:
             destino = lista.copy()
         destino.append(valor)
         return destino

     numeros = [1, 2, 3]
     r1 = agregar(numeros, 4, in_situ=True)
     print(r1 is numeros)           ->  True
     print(numeros)                 ->  [1, 2, 3, 4]
     r2 = agregar(numeros, 5, in_situ=False)
     print(r2 is numeros)           ->  False
     print(numeros)                 ->  [1, 2, 3, 4]
     print(r2)                      ->  [1, 2, 3, 4, 5]

 Cómo funciona la función: el parámetro in_situ decide qué objeto se
 modifica.
     in_situ=True   destino es la misma lista que llegó. El original cambia y
                    lo que se devuelve es ese mismo objeto.
     in_situ=False  destino es una copia. El original no se toca y se
                    devuelve una lista nueva.

 Cuándo conviene cada una: mutar in situ ahorra memoria y es útil cuando
 se quiere que el cambio se vea en todas las referencias. Devolver una copia
 es más seguro porque evita efectos inesperados en el resto del programa.

 7. CONCLUSIONES
------------------------------------------------------------------------------

   - En Python las variables no guardan datos: apuntan a objetos. Asignar
     (b = a) copia la referencia, no el objeto.
   - Con objetos mutables (list) dos referencias al mismo objeto significan
     que un cambio por una afecta a la otra: eso es el aliasing.
   - Con objetos inmutables (int, str, tuple) no hay ese problema, porque
     "modificar" siempre crea un objeto nuevo.
   - Para tener una lista independiente hay que copiarla: copy() o list()
     para listas simples y deepcopy() para listas anidadas.
   - Al diseñar funciones hay que decidir de forma explícita si se muta el
     parámetro o se devuelve una copia, y dejarlo claro a quien la use.
   - Esta idea es la base de la semana siguiente: en las listas enlazadas
     cada nodo guarda una referencia al siguiente nodo.
